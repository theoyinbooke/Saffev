## Round 2 — 2026-07-28 — the injection fix

`commits_for` now emits all of Saffev's own `git log` options first, then
`--end-of-options` before the untrusted branch, so a `--output=`/`--exec=`
style branch is read as a (nonexistent) revision — git rejects it with a
fatal error and the call fail-softs to empty. A regression test builds a
real repo and asserts the `--output=PWNED` payload writes no file. The
named residual risks (no off-machine anchor; between-tick capture gaps) are
honest boundaries, documented in the artifact and not claimed away.
