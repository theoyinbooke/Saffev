# Linux packaging (G8) — status and plan

> Status: **partially landed, CI/VM-verification pending.** The verifiable
> pieces (Homebrew installer, cargo-deb/rpm metadata, systemd user unit) are in;
> the deb/rpm CI job and a real clean-VM install/uninstall test are NOT done and
> must be before any release claims "install with apt/dnf". This file is the
> honest record of what works and what doesn't yet.

## Why not "cargo-dist installers = deb/rpm"

cargo-dist (dist) does not generate native Linux packages. Its installer set is
`shell · homebrew · msi · npm · powershell · pkg` — no deb, no rpm. Adding them
there is impossible, so Linux packages are built by the standard separate tools
and attached to the release, following the same post-announce-job pattern the
macOS DMG already uses (registered in `dist-workspace.toml` so `dist generate`
never clobbers them).

## Landed (verifiable now)

- **Homebrew tap installer** (`installers = ["shell", "homebrew"]` in
  `dist-workspace.toml`). Works on Linux and macOS, needs no new hardware, and
  is generated by dist itself. `brew install theoyinbooke/tap/saffev`.
- **`[package.metadata.deb]`** (cargo-deb) and
  **`[package.metadata.generate-rpm]`** (cargo-generate-rpm) in `Cargo.toml`.
  Inert to every other build — read only when those tools run. Package the
  release binary, the README, and the systemd user unit.
- **systemd user unit** (`packaging/systemd/saffev.service`): supervises the
  Cooperative proxy + Studio on headless/server Linux, the analog of the macOS
  menu-bar app. `--no-open` (no browser on a server). Does NOT enter Gateway
  mode (that still needs `mode = "gateway"` + `saffev adopt`).

## Not done (needs CI + a clean VM)

1. **The deb/rpm CI job.** A post-release workflow that installs `cargo-deb` +
   `cargo-generate-rpm`, runs them against the built x86_64/aarch64 binaries,
   and uploads `.deb`/`.rpm` to the release. Must be registered in
   `post-announce-jobs`. Not written yet because it cannot be tested here and a
   broken release job is worse than none — write it against a branch and watch
   it run before merging.
2. **Clean-VM install/uninstall test** (the G8 rubric): install the `.deb` on a
   fresh Ubuntu and the `.rpm` on a fresh Fedora in ≤ 2 commands, start Studio,
   then uninstall and confirm `revert` restores the pre-Saffev state with no
   residue (journal-verified). None of this can run on the maintainer's macOS
   machine.
3. **Tray on Linux.** The tray code (`src/cli/tray.rs`, `tray-icon` + `tao`)
   already compiles for Linux — it is gated by the `tray` *feature*, not by
   `cfg(macos)`. Enabling it means: build the Linux artifact with
   `--features tray`, add the build+runtime deps (`libgtk-3-dev`, appindicator),
   and verify it degrades gracefully on trayless DEs (the LM Studio #576 failure
   mode is the anti-reference — it must never crash, only be absent). Feature
   compiles; real-desktop behavior is unverified.

## The rule this follows

Per the repo's verification-honesty rule: none of the deb/rpm/tray pieces are
claimed to work in the README until they have run end-to-end on real Linux
hardware. What is committed is the *config and scaffolding* a Linux CI run
needs, plus this note saying exactly where the proof stops.
